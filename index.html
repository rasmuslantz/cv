How I work

Build first. Keep what proves useful.

01

Own the whole path.

Product flow, implementation, APIs, testing, release and documentation are parts of the same system.

02

Make risky logic testable.

Calculations, persistence, migrations, permissions and releases should fail explicitly.

03

Automate state changes.

A workflow should act because something changed, not simply because a timer fired.

04

Archive without pretending.

Some experiments are useful once and then done. Keeping that distinction visible makes active work clearer.
