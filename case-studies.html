Engineering case studies

What happened under the interface.

Feature lists are easy. These are the parts I find more interesting: constraints, architecture, state, failure modes and the decisions that made each product work.

01

DriveSplit · Native iOS

Turning a simple fuel split into deterministic product logic.

The visible product is a route and a number. Underneath, route choice, vehicle consumption, fuel price, passenger count, localization and live trip state all need to agree on the same result.

Problem

Generic expense apps do not understand the journey itself. DriveSplit needed route-aware calculations without making the user manage a spreadsheet of inputs.

Approach

Keep calculation logic separate from presentation, make route choice explicit, persist stable entities such as vehicles and trips, and keep live-session state transient.

Engineering

SwiftUI, SwiftData, MapKit, ActivityKit, GPS filtering, localized decimal handling and XCTest around invalid states and cost logic.

Result

A consumer flow where the UI stays simple while the underlying model remains testable and predictable.

02

PinShift · macOS

A desktop utility spanning UI, native code and physical devices.

Location testing on a real iPhone is not one API call. It crosses a Mac app, USB device communication, Apple development requirements, local state and release trust.

Problem

Device state is messy. A tool has to distinguish disconnected, untrusted, incompatible and ready states instead of turning everything into a generic error.

Approach

Separate the React UI, Tauri/Rust native boundary and Python device bridge, with compatibility checks before simulation work begins.

Safety

Trust, Developer Mode, signing and device ownership are treated as hard product boundaries. Diagnostics are useful but intentionally redacted.

Release

Signing, notarization, updater trust, entitlements and release attestation are treated as part of the product itself.

03

Illa del Bosc Pàdel · Cross-platform

Building a reservation system around real community rules.

A court-booking app becomes interesting when availability, household access, booking limits, admin closures, open matches and multilingual community content all share the same source of truth.

Product

Residents can see live availability, create or cancel bookings, publish open matches, view rules and community information, and use the same product on iOS, Android and web.

Backend

Supabase Auth, Postgres and Row Level Security enforce invite-only access and booking permissions close to the data layer.

Architecture

Expo Router, React Native, TypeScript, TanStack Query, React Hook Form, Zod and migration-driven Supabase infrastructure.

Admin

Closures, invite codes, announcements, rules, schedules and policy changes live in a role-protected workspace rather than requiring manual database edits.

04

Automation systems

Automating state changes, not producing workflow noise.

The useful part of automation is deciding when something meaningful changed, validating it, and making the next action reliable.

Pattern

Trigger → normalize → compare → validate → act → log. The workflow should be understandable even when the happy path fails.

Tools

n8n, REST APIs, webhooks, structured JSON, JavaScript/Python helpers, GitHub and AI-assisted processing.

Reliability

Idempotency, explicit error branches, change detection and traceability reduce duplicate actions and silent failures.

Use cases

Support workflows, ecommerce operations, document routing, repository automation, structured generation and internal tooling.

05

Neon Swipe · Consumer mobile

Making deletion feel fast without making it feel unsafe.

The interaction is deliberately tiny: one photo, one decision. The product work was mostly about progress, undo, recovery and keeping the flow frictionless.

Interaction

Right to keep, left to remove, with filtering by media type and a simple queue model.

Safety

Undo, progress feedback and platform recovery reduce the anxiety of destructive actions.

Product site

A bilingual, lightweight public frontend presents the app without exposing implementation source.

Lesson

Simple consumer products are often more about reducing decisions than adding features.
